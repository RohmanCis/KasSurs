## Design Specificity Verdict

**LLM assessment: Grounded, not interchangeable.** Speed-Tap roster is a workflow invented for this exact scene (treasurer tapping a 30-name roster mid-meeting). PassbookCard translates the paper buku-kas mental model. Per-section color-coded headers give spatial memory ("I'm in the money-out place"). Zero V1.0 token residue; tokens/shadow/press/typography uniform across 6 surfaces. Generic zones: /laporan (two cards + select) and /login ("Bcrypt Hash" badge = developer cosplay). Missed character: no org name after login; WA exists only to chase money, never as receipt; /laporan copy says "siap share WA" but flow ends at download.

**Deterministic scan: clean.** Zero findings in both `src/app` and `src/components` (exit 0). Detector confirms no stale token patterns, no banned markup patterns in scanned trees.

**Visual overlays: none.** Browser injection skipped — login-gated app without a live authenticated session. No user-visible overlay exists; fallback signal is the source-level scan above.

## Overall Impression

A committed, product-native interface with genuinely sophisticated payment-flow design (409 settle-to-truth, graded undo architecture, honest copy), undermined at the edges by a contradictory report header, an invisible rapel gesture, nested-interactive markup, and a login screen that briefly talks to developers instead of treasurers. Biggest opportunity: fix the peak-end — the monthly export, the treasurer's final act, ends in silence.

## What's Working

1. **409 flow as design philosophy.** Duplicate tap settles to server truth: card goes Lunas with real `createdAt`, drawer opens on existing record, toast explains. Error handling as wayfinding — senior-level.
2. **Undo architecture with graded consequences.** Toast undo (no confirm) vs drawer delete (confirm + audit-log consequence copy) encodes destructive intent in the UI; distinct haptics reinforce non-visually; two-layer BARU badge survives refresh without schema changes.
3. **Copy that treats the treasurer as adult and beginner simultaneously.** "Dia tidak bisa login lagi, tapi seluruh riwayat pembayarannya tetap tersimpan" answers lockout + data-loss fears in one sentence. Zero leaked error codes.

## Priority Issues

**[P1] /laporan header badge contradicts the filter.** `laporan/page.tsx:77` badges the *current* month from `now`, never the FilterBar state. User selects Juli, header says September, file downloads as `laporan-kas-2026-07.xlsx`. Beginner treasurer reads: "did I export the wrong month?" Fix: badge reflects selected `bulan/tahun`. Suggested command: /impeccable polish

**[P1] Long-press is the sole door to rapel, and it's invisible.** 450ms pointer-only gesture (`pembayaran/page.tsx:580` caption, 10px gray), no keyboard equivalent; Enter/Space on a Belum card fires an instant Rp30.000 payment. Rapel is a common kas scenario, not an edge case. Jordan never finds it; Sam cannot reach it. Fix: explicit per-card "nominal lain" affordance or header "Mode Rapel" toggle + keyboard path. Suggested command: /impeccable shape

**[P1] Nested interactive elements break AT/keyboard.** `<a>` (WA) inside `<button>` (`anggota/page.tsx:465` in 423); `<button>` inside `div role="button"` (`MemberCard.tsx:173` in 115). Screen readers announce button-inside-button; focus order unpredictable; `stopPropagation` doesn't fix the ARIA tree. Fix: restructure so expander and WA action are siblings. Suggested command: /impeccable harden

**[P2] Expense success toast never dismisses.** `pengeluaran/page.tsx:115` `duration: Infinity`, top-center (max thumb distance): yellow slab parks over header until "Input Lagi" — which also resets the form, conflating dismissal with action. Successive saves stack. Fix: ✕ close or ~6s auto-dismiss. Suggested command: /impeccable polish

**[P2] Login speaks developer, not treasurer.** "Bcrypt Hash" badge (`LoginForm.tsx:187`) on the first screen a beginner sees; forgotten PIN is a dead end (only "salah"/"terkunci", no "hubungi admin untuk reset"). Fix: drop badge; add "Lupa PIN? Hubungi bendahara untuk reset." Suggested command: /impeccable clarify

## Persona Red Flags

**Sam (screen reader / keyboard / contrast):**
- Nested interactives corrupt ARIA tree (both P1 locations above).
- Long-press rapel has no keyboard path — keyboard-only treasurer cannot record any non-default payment.
- Focus rings `focus:ring-neo-yellow` (#FEF08A on #FFFDF0 ≈ 1.1:1) in MemberForm, FilterBar, login noHp — effectively invisible. Standardize on `ring-black`.
- Good: aria-pressed/expanded/current, role=alert + aria-live, radiogroup chips, per-digit PIN labels.

**Casey (one-handed mobile, meeting scene):**
- **Undo BATALKAN at top-center** (`layout.tsx:29`) — most time-critical button (5s window) at max thumb distance during bottom-half roster tapping.
- WA buttons ~22px (`MemberCard.tsx:177`) / ~28px (`anggota/page.tsx:471`) — under 44px, nested inside another tap target → fat-thumb misfires.
- Good: roster cards 72×200px, 44px chips/nav, safe-area inset, touch-action manipulation.

**Jordan (first-timer, tech beginner):**
- "Bcrypt Hash" jargon; no forgotten-PIN recovery path (Jordan's most likely failure = dead end).
- Rapel discoverability (P1) — second-most-important flow hidden behind a gesture Jordan never used.
- "Bendahara Aktif" reads as status, not place — "Ringkasan Kas" orients better.
- Good: lockout copy warm and specific ("coba lagi dalam 12 menit"), success states loud, empty states carry next-action text.

## Minor Observations

- Toast action style split: `NEO_ACTION_STYLE` white/black (/pembayaran) vs black/yellow (/pengeluaran) — doc 5.7 says putih/hitam won; pengeluaran stale.
- `pengeluaran/page.tsx:228` "Coba lagi" bare underline — only non-neo-press interactive in the app, ~16px.
- Register mix: kamu (login, anggota) vs Anda (passbook, 404, error) — pick "kamu".
- /pembayaran shows no period label — one badge closes the loop.
- Export success silence — one toast "Laporan September 2026 terunduh" fixes the peak-end.
- `Rp 30k` (cards) vs `Rp 30.000` (toast) — same payment renders two ways within one second.
- `text-[8px]` status pill on MemberCard — below comfortable minimum for 50+ treasurers; 9px floor elsewhere.
- tabular-nums gaps: sonner toast root lacks it for formatRupiah; header period years; PassbookCard "TH. {tahun}". Cosmetic.

## Questions to Consider

1. The WA button only exists to chase money. Why no WA receipt after recording lunas — one tap sends proof and kills every "sudah bayar kok belum tercatat" dispute at the source?
2. Recording Rp30.000 gets a 5-second undo and a badge; downloading the organization's official monthly report gets silence. What does that say about which action the app considers important?
3. The treasurer's real audience is a WhatsApp group. If the report's destination is WA ("siap share WA" is the app's own copy), why does the flow end at a download instead of a share sheet?
